Tsclp_v2.2_volatile — скальпинг-робот с выбором топ-10 волатильных акций

Только песочница. Реальные сделки запрещены.

Отличия от Tsclp_v2.0
- Инструменты не фиксированы. Скрининг выбирает топ-10 волатильных акций MOEX.
- Фильтр ликвидности: средний дневной оборот не менее 10 млн рублей.
- Кэш скрининга: 24 часа.
- Если скрининг не удался, новые входы запрещены (неполное сканирование не используется как TOP-10).
- Fallback на SBER/GAZP отключён.

Безопасность: trading.flag
Новые входы запрещены по умолчанию.
Наличие файла trading.flag в корне проекта разрешает открытие новых позиций. Отсутствие файла запрещает.
- Запуск программы не создаёт trading.flag автоматически.
- Чтобы разрешить новые входы, создайте файл вручную (или через Telegram-команду /start_trading).
- Чтобы запретить новые входы, удалите файл (или /stop_trading).
- Не коммитьте trading.flag в Git (он в .gitignore). Иначе после клонирования торговля будет разрешена автоматически.
- Запрет новых входов не отключает мониторинг и сопровождение уже открытых позиций.

Запуск (Windows, .venv)
1. Клонируйте репозиторий или скопируйте папку проекта.
2. Создайте виртуальное окружение .venv:
   python -m venv .venv
3. Активируйте:
   .\.venv\Scripts\Activate.ps1
4. Установите зависимости:
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
5. Заполните .env (см. ниже).
6. Запустите тесты:
   .\run_tests.ps1
7. Запустите робота:
   .\.venv\Scripts\python.exe main.py

Новые входы запрещены по умолчанию. Чтобы разрешить, создайте trading.flag (см. выше).

.env — переменные
Создайте .env в корне проекта (не коммитится):
TINKOFF_API_TOKEN=...
TINKOFF_READONLY_TOKEN=...
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
TELEGRAM_ALLOWED_USER_ID=...
TINKOFF_ACCOUNT_ID=...
STARTING_BALANCE=100000

- TINKOFF_API_TOKEN — Sandbox-токен (торговый).
- TINKOFF_READONLY_TOKEN — read-only токен (для скрининга).
- TELEGRAM_* — для Telegram-бота (если ENABLE_TELEGRAM=True).
- TINKOFF_ACCOUNT_ID — ID счёта (если не задан, используется первый Sandbox-счёт).
- STARTING_BALANCE — начальный баланс для отчёта check_sandbox.py.

Не коммитьте .env. Он в .gitignore.

Sandbox-only
USE_SANDBOX=False запрещён. TinkoffClient бросает SandboxRequiredError. Реальный контур не реализован.

Диагностика
- check_sandbox.py — отчёт по песочнице (P&L, комиссия, позиции). Read-only.
- diagnose_sandbox.py — ручная диагностика (портфель, свечи, стоп-заявки). Требует --yes. Read-only.
Оба скрипта не отправляют заявок. Только чтение.

Аварийное закрытие позиций
close_all_positions.py — ручное закрытие LONG-позиций после подтверждения YES.
- SHORT обнаруживаются, но BUY не отправляется (семантика buyMaxLots для закрытия шорта не подтверждена).
- Lock-файл (close_all_positions.lock) запрещает параллельный запуск.
- Использует GetSandboxMaxLots → sellMaxLots.
- Финальная сверка: если позиции остались, сообщает, не заявляет успех.
- Не запускается автоматически из main.py.

close_lsrg.py и close_all_positions_v2.py — удалены из проекта (архив в archive/). Не запускать.

pay_in.py
Ручное пополнение песочницы на 100 000 рублей. Только Sandbox. Требует YES. Не запускать автоматически. В торговом цикле не используется.

Ограничения
- Скрининг делает много запросов к API. При 200+ акциях — несколько минут.
- 10 инструментов не равно 10 позициям. Риск-менеджер ограничит одновременные позиции.
- Прибыльность не подтверждена.
- Частичные исполнения обрабатываются через applied_lots; при расхождении — UNCERTAIN.
- Reconcile двусторонний (FIGI + количество + направление).

Будущие улучшения (не реализовано)
- Трейлинг-стоп / перевод в безубыток (в execution.py, после двухнедельного исследования).
- Выход по обратному пересечению MA (сейчас только SL/TP).
- Адаптивный STOP_LOSS_PERCENT для волатильных бумаг.
- Исправить (не сейчас) — notify только при изменении расхождения (дедупликация), а не каждый цикл.
- При расхождении заявки с локальными записями - предложить в ТГ выбор: оставить/продать/докупить еще . 

# комменты аудиторов:
реальные баги, часть — критичные для самой стратегии:
Один StrategyManager на все 10 инструментов (критично). В main.py создаётся один sm, а состояние ADX-режима (_last_regime, _regime_streak, _last_regime_candle_time) — на инстанс, не на FIGI. У всех бумаг одинаковые таймстемпы 5-минуток, поэтому второй и последующие тикеры в цикле попадают в ветку «повторный вызов на той же свече» и получают режим первой бумаги в списке. Хуже того: их кандидаты сбрасывают _regime_streak, так что гистерезис ломается и для первой бумаги. Итог: режим определяется фактически одной бумагой, а данные исследования (regime в jsonl) загрязнены. Фикс: dict[figi → StrategyManager].
Провал скрининга убивает мониторинг. В main() при неудачном скрининге — while True: sleep(60) до входа в торговый цикл. Открытые позиции из state.json остаются без SL/TP-контроля. Это прямо противоречит README («запрет входов не отключает мониторинг»). Надо продолжать цикл с пустым списком входов.
Скринер запускается один раз при старте. Кэш 24 ч есть, но периодического рескрининга в цикле нет — TOP-10 заморожен на всё время жизни процесса.
Нет календаря сессий. Робот крутится 24/7 (в sandbox_pnl.csv есть строка от воскресенья 15.11). В песочнице заявки «исполняются» по последней цене и в выходные — статистика исследования загрязняется. Плюс CANDLES_LOOKBACK_DAYS=2 — календарные дни: в понедельник утром свечей после выходных мало, фильтры MA100/60 свечей блокируют сигналы до второй половины дня.
Оборот в скринере считается неверно. У T-Invest API объём свечей — в лотах, а формула mean(volume) × mean(close) не умножает на lot_size. Для бумаг с лотом 10 фильтр 10 млн ₽ фактически превращается в 100 млн ₽ (проверь на контрольном примере). Плюс произведение средних ≠ средний оборот.
Сигнал живёт 5 минут. Пересечение MA на закрытой свече перевычисляется каждые 30 с. После стопа внутри той же свечи возможен повторный вход по тому же протухшему сигналу (до 5 раз/день) — классический источник «пилы». Нужны дедуп «одна сделка на сигнальную свечу» и лимит отклонения цены входа от close сигнальной свечи.
SL/TP только клиентские, поллинг 30 с, выход market-заявкой. Песочница исполняет по last price без стакана — модель проскальзывания 0.02% для волатильного 2-го эшелона оптимистична в разы (реальный спред там 0.1–0.5%). При обрыве связи позиция вообще без защиты.
Риск-модель не сходится с декларацией. RISK_PER_TRADE=1% недостижим: при потолке 20% капитала и SL 1.2% реальный риск ≈ 0.24% (видно по сделке SMLT: 68×291 ≈ 19.8 тыс. ₽). Это консервативно, но конфиг вводит в заблуждение. И нет дневного kill-switch по убытку, нет cooldown после серии стопов, нет лимита суммарного «горячего» риска.
Мелочи: state.json, research_trades.csv, sandbox_pnl.csv, __pycache__ закоммичены вопреки README; в sandbox_pnl.csv битая строка (7 полей при 6 в шапке) и артефакт «−100%» до pay_in; заголовки файлов v2.2 в репо v2.1; мёртвый POSITION_QUANTITY_IS_LOTS; профиль FORCE_TRADE (MA 2/3, ADX>5) опасен при случайном включении.
Что бы я поменял ради выгоды
Сначала честный фрейминг: это не скальпинг. TP 2.4–6% при SL 1.2–3% с поллингом 30 с — это удержание часами и овернайт (нет принудительного закрытия к концу сессии — гэп против стопа 1.2% съедает месяцы прибыли). Настоящий скальпинг требует стриминга (MarketDataStream), стакана и лимитных заявок — на REST-поллинге его не сделать. Поэтому менять надо в сторону «быстрый интрадей», а не «больше сделок».
Математика отрезвляет: при SL 1.2% / TP 2.4% и реальных издержках ~0.3–0.5% за круг (комиссия + спред) безубыточный винрейт ≈ 42–45%. Пересечения MA9/21 на 5-минутках столько дают не всегда — преимущество на грани и должно быть доказано, а не предполагаться.
Приоритеты:
Сначала корректность, потом доходность: фиксы п.1–6 выше. Сейчас вы исследуете стратегию, которая торгует не то, что описана.
Сессия и время: торговать только основную сессию, отдельный режим (или пропуск) первых 10–15 мин и последнего часа; flat к концу дня; time-stop «нет прогресса за N свечей → выход».
Выходы под режим (самое дешёвое улучшение RR-профиля):
TREND: фиксация 50% на 1R → безубыток → трейлинг по ATR/MA9 вместо фиксированного TP 2R; выход по обратному пересечению MA (у вас в планах).
RANGE: цель — средняя линия Боллинджера (~0.5–1%), а не 2.4%. Возврат к среднему с таргетом 2R структурно убивает винрейт; тут нужен RR≈1:1 при винрейте 55–65%.
Издержки — главный враг скальпера: фильтр спреда по стакану (пропуск, если спред > ~0.15–0.2%), вход лимиткой у bid/ask вместо market, требование «ожидаемое движение ≥ 3–5× издержек круга». Комиссию брать по реальному тарифу.
Отбор бумаг: абсолютный топ ATR% — это ловля «ножей» и новостных пампов. Лучше относительное расширение волатильности (ATR сегодня vs собственная медиана за 30 дней) + корректный оборот в ₽ + спред. Топ-10 волатильных MOEX сильно скоррелированы — лимит 2–3 одновременных позиции и разнесение по секторам.
Риск-контур: дневной kill-switch (−2…−3% капитала → стоп до завтра), cooldown после 2–3 стопов подряд, суммарный открытый риск ≤2–3%, привести RISK_PER_TRADE в соответствие с капитал-кэпом.
Валидация: у вас есть соседний репо MOEX_HISTORICAL_LAB_2Y — прогоните стратегию на 1–2 годах 5-минуток с реалистичными издержками, walk-forward, и только потом песочница для механики (у вас это уже правильно задекларировано). По двум сделкам (+211 ₽ net) о прибыльности судить нельзя — README честно это признаёт.
Итог: как инженерный каркас — крепко, местами образцово для пет-проекта. Как торговая система — пока не доказана, а главный баг (общий ADX-режим на все бумаги) означает, что текущие результаты исследования не отражают задуманную стратегию. Я бы начал именно с него и с сессионного фильтра — это дешевле любых новых индикаторов и сразу повышает и качество данных, и ожидаемый результат
